Problem
문제 정의

전화 예약·종이 문진으로 운영되는 동물병원에서는 보호자가 “지금 병원에 가야 할 응급인지”를 스스로 판단하기 어렵습니다. 수의사는 진료와 행정 업무를 동시에 처리해야 하고, 상담·문진·예약·진료·처방·경과 기록이 서로 끊겨 있습니다.

Pain

흩어진 진료 여정

  • 상담 → 예약 → 진료 → 처방 → 경과가 각각 다른 채널·종이로 단절
  • 보호자는 응급도 판단이 어렵고, 수의사는 사전 정보 없이 진료 시작
Solution

해결 방향

  • 보호자의 말 한마디가 상담·문진·예약·처방까지 이어지도록 설계
  • 응급은 즉시 내원 유도, 일반은 RAG 기반 문진으로 사전 정보를 모아 수의사에게 전달

Deep Dive
문진 대화 개선 — 평가셋으로 찾고 같은 200건으로 다시 확인

문진 200건을 실행한 뒤 대화의 문제를 유형별로 나누고, 다른 수정과 섞이지 않게 하나씩 고쳐 같은 200건으로 재실행했습니다.

찾은 문제

보호자 답과 이어지지 않는 문진

  • 마무리 답변이 보호자 증상 대신 사례 검색 결과를 설명 (“검색된 사례 기준으로는…”) — 200건 전부
  • 질문이 보호자의 앞 답변과 이어지지 않음
  • 증상 나열 뒤 “예약을 도와드릴까요?” 한 문장으로 고정된 마무리, 연달아 반복되는 공감 표현
  • 예약 후 발작 같은 응급 경과에서 LLM 답변이 비면 기본 저장 안내 문구가 출력 (안전성 684건에서 16건 발견)
바꾼 것

한 턴에 질문 하나, 직전 답에서 시작

  • 문진 프롬프트의 말투 지시만 먼저 고쳐 따로 실행해 비교
  • 한 턴에 질문 하나만 하고, 직전 답변을 받는 한 구절 뒤에 질문을 연결
  • 공감 표현은 반복하지 않도록 지시, 20건으로 먼저 확인한 뒤 200건에 적용
  • 응급 경과에는 전용 공감 문구와 더 빠른 예약 시간 즉시 제안을 추가
결과

같은 200건 재실행에서 검색 결과를 언급한 대화 200 → 0건, 질문 연결률 58 → 72%, 고정 문구로 끝난 대화 199 → 0건. 문진 199/200건 완료, 평균 3.7턴.

PM을 맡아 범위와 진행을 조율하고, 평가셋 설계와 문진 대화 개선, 병원 입점·예약 후 경과 관리 기능, 배포 안정화를 담당했습니다.

  • 응급 신호면 내원 안내, 응급 경과 전용 공감 문구 + 더 빠른 예약 시간 제안
05 · MULTI-TENANT

병원 입점 · 멀티 테넌트 확장

  • 병원별 입점 신청 → 운영자 승인 → 계정 일괄 발행, 환자·EMR 데이터 병원별 분리
  • 보호자 계정 하나로 여러 병원 등록
06 · MODEL CHECK

응급을 낮게 본 건수 별도 집계

  • 메시지 1건 응급도 분류, 30건을 5번씩 반복해 모델 비교
  • 정확도 88.7% 모델은 긴급 사례 2건을 한 단계 낮게 분류, 76.6% 모델은 0건
  • 정확도가 높아도 응급을 놓치면 위험하다는 기준으로 비교
